**First-successor field scope.** A valid cleanup of older monthly history does not, by itself, change independently supplied as-of fields. On an eligible open account, a latest adverse month actually suppressed by the bank can support elected current status when the supplied as-of status agrees with that adverse code and the other fields support that basis. At closed status 13, the relevant evidence is the rating at closure and the original month immediately preceding the known closure. At paid derogatory statuses 61–65 the engine checks whether the corresponding severe basis was actually removed and whether a separate adverse basis survives. The successor records the field rule in `account_field_policy` and unresolved evidence in `account_field_review_reason`. The sparse date output still supports reading a populated replacement from a historical export. An eligible missing date requires source research. A proposed whole-tradeline deletion carries the separate `DA` instruction.

## Boundaries that remain

- **Monthly operations.** A fresh study generates account incident dates. With the original source history and account summary updated in the same database, a reviewer can opt into rerunning Module 2 with the prior fixed dates. Reassessment replaces the current snapshot only after checking saved incident dates and per-account cutoffs. An external archive of prior evidence and reviewer decisions supports historical reconstruction. Agreement of local copies cannot authenticate coordinated alteration of every copy. A deletion proposal clears this model’s cure-review flag. Bureau delivery, acknowledgments and any subsequent refurnishing decision are separate operational steps. [Rerun instructions](tools/RUN_STUDY.md)
- **Reversal evidence.** A numeric original history mark after the latest severe event serves as a proxy for reversal in synthetic data. The SQL records the first such observation. Confirm a real reversal against servicing records. An original `5`, for example, still describes delinquency and provides no qualifying current month for cure.
- **Reporting fields and causation.** The generator uses fixed synthetic policies for status, rating and date of first delinquency. It does not establish whether an actual bank error caused a particular late payment. Its delinquency-date calculation looks for numeric delinquency in the latest uninterrupted adverse run. The Field 25 source exception screen above covers retained accounts with known status/rating requirements, including closed accounts. A real correction needs servicing evidence and applicable furnishing guidance.
- **Population and calendar.** The same account number can fall into a different base profile at a different population size. Comparisons in this audit pair the same population and configuration across code versions. The evaluated account months are historical observations. Cure confirmation is the last month needed to meet the configured threshold, including the third original current month in the default study or the fourth in the alternative study.
- **Test coverage.** Native execution used PostgreSQL 16.2 and PowerShell 7.7 on Linux. Windows PowerShell 5.1 compatibility was reviewed in source. The five-million-account default has no measured runtime or load-test result here. The spring dashboard separately illustrates 500 simulated accounts with a 10,000× display multiplier. Imported production feeds, bureau submissions and downstream bureau responses were outside the execution scope.

**Source-D regression coverage.** The independently recounted 25,000-account study had 484 accounts with an original `D` somewhere in history. None has an original `D` in the latest position. Seventy-four cleanup accounts have an earlier original `D`. The unchanged-latest-`D` guard therefore required controlled open, unclassified, closed and deletion cases. A native before/after comparison found zero row differences in the four Module 2 outputs on the 25,000-account population. The favorable latest-month election accounted for all 2,340 proposed date clears in that cohort.
